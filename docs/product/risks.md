# Overtone — Risk Register

Scale: likelihood / impact each **L=1, M=2, H=3**; score = L×I. Review at every increment exit; a risk whose score rises two increments running gets scope taken from the roadmap, not a stronger mitigation sentence.

Not legal advice. The legal-privacy rows describe a compliance *surface* we must consciously choose how to handle; several of them need a qualified opinion before we take audio from users other than ourselves (see Q6, Q7 in [`open-questions.md`](./open-questions.md)).

## Cheapest early de-risking experiment per risk

Every one of these is ≤2 days and most are ≤2 hours. "Kill criterion" = the observation that forces a plan change, not a stronger promise.

| ID | Cheapest experiment | Cost | When | Kill criterion |
|---|---|---|---|---|
| R1 | Transcribe 5 real recordings (one deliberately bad: phone on a table, 3 people) through 2 providers; hand-count 20 terms; compute keyword recall. | ~3 h, <$2 | **Before M0 code** | Best provider <85% recall on realistic audio ⇒ reposition around transcript search, not counting |
| R2 | In that same spreadsheet, list every surface form the ASR produced for 5 chosen terms. | ~30 min, $0 | with R1 | >3 unmatched variants per term ⇒ synonym sets are M2 scope, non-negotiable |
| R3 | Transcribe one 90-minute recording; read the actual invoice line; divide. | ~15 min, <$1 | Before M1 | >$0.50/audio-hr on the cheapest acceptable tier ⇒ revisit Q2 (local model) |
| R4 | `messages.count_tokens` on one real 1-hour transcript, multiply by a 50-hour library, price at `claude-opus-5` rates. Then write the SQL that answers "how many times ever" from an aggregates table and price *that* (flat ~3–5k tokens). | ~1 h, <$1 | Before M2 schema | Aggregate path isn't ≥50× cheaper, or its cost grows with library size ⇒ rethink the assistant's architecture before building M2's storage |
| R5 | Try to hit the M0 upload endpoint from an incognito window with no secret. | ~10 min, $0 | M0 exit | It works ⇒ don't share the URL with anyone |
| R6 | Deploy a 10-minute dummy job on the target platform and watch whether it survives. | ~1 h, $0 | Before M1 commits | Dies at a request timeout ⇒ constrains hosting choice; tell architecture now |
| R7 | Submit the same file twice to the M0 pipeline. Count the invoice lines. | ~15 min, <$1 | M0 exit | Two charges ⇒ idempotency key is the first M1 commit |
| R8 | Upload a 400 MB file over a throttled connection; kill wifi mid-upload. | ~1 h, $0 | Before M1 upload work | Unrecoverable or silently truncated ⇒ resumable direct-to-storage before anything else in M1 |
| R9 | Write the 3-sentence consent attestation and read it back as a hostile user. | ~30 min, $0 | M0 | Can't state it honestly ⇒ positioning problem, escalate before public signup |
| R10 | Read the shortlisted providers' DPA, retention and training terms. Write the data flow on one page. | ~2 h, $0 | **Before M1 vendor commit** | No zero-retention option or no DPA ⇒ provider is disqualified regardless of price/accuracy |
| R11 | Delete a recording in M0's prototype; then check storage for the blob. | ~20 min, $0 | M1 | Blob survives ⇒ deletion is a correctness bug, fix before any external user |
| R12 | Run diarisation on 3 real multi-speaker recordings; hand-label talk-time; compare. | ~2 h, <$1 | Before M3 commits | >15 pp error ⇒ cut diarisation from v1 entirely, say so in Q8 |
| R13 | Feed one non-English and one code-switched clip through the chosen provider with language detection off. | ~30 min, <$1 | Before M4 | Returns confident English nonsense ⇒ detection + warning banner is M4-blocking |
| R14 | Write the one-sentence precondition for assistant work into this register and the roadmap. Done. | ~5 min, $0 | now | Any assistant work starts before M2's bar passes ⇒ stop and re-read |
| R15 | Get the stakeholder to name 2 reference products and tick 10 checklist items. | ~45 min, $0 | By M2 | They won't commit to a list ⇒ M4 is uncappable; cap it at 2 weeks unilaterally and show the result |
| R16 | Hand-make the output for 3 real recordings in a spreadsheet; show 5 target users; ask "what would you do differently?" | ~3 h, $0 | **Before M2 UI** | Nobody names an action ⇒ watchlists/trends aren't the product; find the real question before building M2 |
| R17 | Keep the M0 ASR call behind one interface with a fixture double from the first commit. | ~1 h, $0 | M0 | Provider calls leak into business logic ⇒ refactor before M1 |
| R18 | From R1's data, sort recall by recording. Look at the spread. | ~20 min, $0 | with R1 | >2× spread ⇒ per-recording confidence indicator is v1 scope, not nice-to-have |
| R19 | Re-forecast M3–M6 from actual M0–M2 throughput. | ~30 min, $0 | M2 exit | Actual >1.5× estimate ⇒ cut M6 and re-scope M5, don't compress quality |

**Sequencing note.** R1, R2, R16 and R18 share one afternoon of work on the same 5 recordings, before a line of M0 code is written — roughly 4 hours and under $5 against the four risks that most plausibly invalidate the product. R10's vendor-terms review gates the M1 provider commitment and cannot be deferred past it.
